1. ABSTRACT
================================================================================

The Undersea Cable Failure Detection System is a centralized, real-time diagnostic and monitoring platform designed to secure and optimize international communication and power transmission grids. Undersea cables form the critical backbone of global data and electricity distribution, carrying over 97% of transoceanic internet traffic; however, physical damages from ship anchors, fishing trawlers, insulation wear, and seismic stress often lead to severe operational disruptions. Traditional manual inspection and physical Time Domain Reflectometry (TDR) remain slow, reactive, and highly expensive, failing to offer automated anomaly classification or instant localization. This project addresses these challenges by developing a full-stack automated pipeline powered by a FastAPI backend and a premium glassmorphic React.js (Vite) dashboard, achieving low-latency streaming of telemetry frames over high-frequency WebSockets at 10-20Hz. The core intelligence comprises a hybrid Conv-Transformer Autoencoder model that processes sliding 60-step temporal window sequences across 9 physical sensor channels, spanning electrical, optical, acoustic, and spatial parameters. To ensure cross-medium versatility, the system implements a 10-channel one-hot domain conditioning registry that dynamically adapts the AI core's feature space to distinct cable segments (e.g., copper electrical vs. fiber-optic). Upon anomaly detection, a dual-head model outputs an unsupervised reconstruction-based Mean Absolute Error (MAE) confidence score alongside a 4-class fault classification (Normal, Short, Open, High-Z), while integrated TDR delay equations pinpoint the exact geographical coordinate of the physical defect. Furthermore, built-in Explainable AI (XAI) feature contribution overlays and an automated ReportLab PDF/CSV export engine produce audit-ready, compliance-compliant forensic logs. Ultimately, the system improves ocean grid reliability and minimizes Mean-Time-To-Repair (MTTR) by delivering an aesthetic, bioluminescent monitoring workspace for proactive maritime risk mitigation and institutional knowledge management.

2. INTRODUCTION
================================================================================

Undersea cables -- both fibre-optic and power cables -- are critical
infrastructure assets. Fibre-optic submarine cables carry over 97% of
international internet traffic, while High-Voltage Direct Current (HVDC)
undersea cables are increasingly used to connect offshore renewable energy
installations to the mainland grid.

Failures in these cables can result from:
  - Physical damage from ship anchors ("anchor drag")
  - Cable cuts from fishing trawlers or natural abrasion
  - Insulation degradation or overheating due to electrical stress
  - Environmental stresses such as seismic activity or extreme temperature

Traditional fault-detection approaches rely on Time Domain Reflectometry (TDR)
and manual inspection, which are expensive, slow, and reactive rather than
predictive. Machine learning-based approaches offer an opportunity for
proactive, continuous monitoring that can detect anomalies before they escalate
into complete cable failures.

This project builds a production-grade, end-to-end automated fault detection
pipeline that unifies real-time sensor ingestion, deep learning inference, and
interactive visual monitoring.

5.2 DATA PIPELINE REFINEMENT
----------------------------
  1. INGESTION: Sensor data is pulled from CSV datasets or the Synthetic Simulator.
  2. NORMALISATION: Features are scaled using a pre-trained MinMaxScaler to [0,1].
  3. DOMAIN CONDITIONING: A 10-channel one-hot vector is appended to represent 
     cable metadata (e.g., depth, age, insulation type).
  4. TEMPORAL SEQUENCING: Sliding windows of 60 samples (6 seconds) are created.
  5. INFERENCE: The model predicts the anomaly score and classifies the fault.
  6. STREAMING: Results are pushed via WebSocket to the dashboard at 10-20 Hz.

7. MATHEMATICAL FOUNDATION
================================================================================

7.1 ANOMALY DETECTION (RECONSTRUCTION ERROR)
--------------------------------------------
The model acts as an "identity function" for normal data. If X is the input sequence
and f(X) is the reconstructed output, the anomaly score (S) is derived from the
Mean Absolute Error (MAE):

    L_rec = (1 / T*F) * Σ | X_i,t - f(X)_i,t |

Where:
  T = Sequence length (60)
  F = Number of features (19)

7.2 FAULT CLASSIFICATION (SOFTMAX ENTROPY)
------------------------------------------
The classification head outputs a probability distribution P over K classes:

    P(y = k | X) = exp(z_k) / Σ exp(z_j)

The final anomaly score used for the dashboard is:
    S = 1 - P(class=Normal)

7.3 LOSS WEIGHTING
------------------
To balance reconstruction (unsupervised) and classification (supervised), we use:
    Total Loss = λ1 * L_rec + λ2 * L_cls
    (Currently λ1=1.0, λ2=2.0)

8. METHODOLOGY & PIPELINE
================================================================================

8.1 DATA COLLECTION
-------------------
The system ingests data from three complementary sources:

  1. Synthetic Simulator (simulator.py)
     Generates realistic multi-modal sensor readings with configurable fault
     injection. Supports four fault types with domain-accurate sensor
     signatures (e.g., voltage collapse for cable cuts, vibration spikes
     for anchor drag).

  2. Azure Predictive Maintenance Dataset
     Real-world industrial sensor readings (bearing wear, pump failures,
     electrical faults) adapted and normalised to the cable fault domain.

  3. Optical Dataset
     OSNR, BER, and optical power telemetry from fibre-optic network
     monitoring systems.

8.2 DATA PREPROCESSING & SEQUENCE ENGINEERING
---------------------------------------------
  Raw Sensor Readings (9 features)
        |
  Reindex to canonical FEATURES list (fill missing with 0.0)
        |
  MinMaxScaler (fit on normal data only -> prevents fault signal leakage)
        |
  Append 10-channel one-hot domain embedding (cable_domain_id)
        -> Total: 19 features per timestep
        |
  make_sequences(): sliding window of 60 timesteps, step=1
        -> Output shape: (N, 60, 19)

8.3 TRAINING STRATEGY & OPTIMIZATION
------------------------------------
  - Dual-output loss:
      MAE reconstruction loss + Sparse Categorical Cross-Entropy,
      weighted 1:2 (classification weighted higher to prioritise
      fault discrimination).

  - Class imbalance handling:
      Minority fault rows oversampled to ~50% of normal count before
      sequencing.

  - Optimiser:
      Adam with Cosine Decay learning rate schedule
      (3x10^-4 -> ~10^-6 over 30 epochs).

  - Gradient clipping: clipnorm=1.0 to prevent exploding gradients.

  - Regularisation:
      Dropout (15%), Early Stopping (patience=12), Model Checkpointing.

  - Train/Validation split:
      Manual 85/15 random split (bypasses a Keras 3.14 validation_split
      squeeze-axis bug on large datasets).

8.4 THRESHOLD CALIBRATION LOGIC
-------------------------------
After training, the anomaly detection threshold is calibrated via an
F1-score sweep over held-out normal data:

  - Reconstruction errors at the 97th percentile on the calibration set
    are used as the initial threshold.
  - find_optimal_threshold() refines it via exhaustive F1 sweep when
    labelled calibration data is available.

9. MODEL DESIGN: CONV-TRANSFORMER HYBRID
================================================================================

9.1 CONV-TRANSFORMER AUTOENCODER
--------------------------------

ENCODER PATH
  Input(60, 19)
    -> Conv1D(128 filters, kernel=3, stride=2, relu)  # -> (30, 128)
    -> SinePositionalEncoding(max_len=68)
    -> TransformerEncoderBlock x 3
         (8 heads, key_dim=16, ff_dim=256, dropout=0.15)
    -> GlobalAveragePooling1D()                        # -> (128,)
    -> Dense(64, relu)  [Bottleneck]

RECONSTRUCTION HEAD
  Dense(30x128, relu) -> Reshape(30, 128)
    -> TransformerEncoderBlock x 3
    -> Conv1DTranspose(128, kernel=3, stride=2)        # -> (60, 128)
    -> TimeDistributed(Dense(19))
  [Loss: MAE, weight=1.0]

CLASSIFICATION HEAD
  Dense(64, relu) -> Dropout(0.15) -> Dense(32, relu) -> Dropout(0.075)
    -> Dense(4, softmax)
  [Loss: SparseCategoricalCE, weight=2.0]
  [Output: P(Normal), P(Short Circuit), P(Open Circuit), P(High-Z)]

ANOMALY SCORE
  anomaly_score = 1 - P(Normal)    in [0.0, 1.0]

    0.0 -> model is certain the reading is Normal
    1.0 -> model is certain a fault exists

9.2 SINEPOSITIONALENCODING
--------------------------
A custom Keras layer implementing canonical sinusoidal positional encoding
(Vaswani et al., 2017), adapted for time-series data. The encoding table is
stored as a non-trainable weight to enable Keras 3.x graph tracing and
serialisation.

9.3 TRANSFORMERENCODERBLOCK
---------------------------
A standard Post-LN Transformer encoder block with:
  - Multi-Head Self-Attention (MHA)
  - Feed-Forward Network (FFN) with ReLU
  - Residual connections + Layer Normalisation
  - build_from_config() implemented for Keras 3 checkpoint deserialization

12. EXPLAINABLE AI (XAI) IMPLEMENTATION
================================================================================

Operational trust is established by showing "why" a fault was detected.

12.1 FEATURE CONTRIBUTION ANALYSIS
----------------------------------
For every detected anomaly, the system calculates the per-feature reconstruction
error. Features with the highest error are identified as the "Root Cause":

    Contribution(f) = (Σ |X_f,t - f(X)_f,t|) / Total_Error

12.2 DASHBOARD OVERLAY
----------------------
The React frontend displays these contributions as percentage badges (e.g.,
"Voltage: 72% | Vibration: 18%"), allowing engineers to immediately distinguish
between an electrical short and a mechanical anchor drag.

15. FUTURE SCOPE & SCALABILITY
================================================================================

  1. Live Hardware Integration
     Connect to physical sensor arrays on real cable infrastructure via MQTT
     or OPC-UA protocols, replacing CSV-based replay with live streaming.

  2. Federated Learning
     Train models at each cable landing station independently, sharing only
     model updates (not raw telemetry) to preserve data sovereignty.

     Expose the full attention weight matrices from each Transformer head in

     Scale the dashboard to monitor multiple cable segments simultaneously

     (Raspberry Pi / NVIDIA Jetson) directly at cable landing stations.

     Integrate Distributed Acoustic Sensing (DAS) data streams from commercial
     fibre interrogation units for higher spatial resolution fault localisation.
